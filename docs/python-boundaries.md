# Границы Python-модулей

Код подготовки и исследований находится в `src/recsys/`. [Политика](../scripts/module_boundaries.json) перечисляет каждый Python-модуль ровно в одной логической подсистеме. [Статическая проверка](../scripts/check_module_boundaries.py) строит граф импортов из AST и запускается в существующей CI job `agent-setup`:

```bash
python3 scripts/check_module_boundaries.py
python3 -m unittest discover -s scripts/tests -p 'test_*.py' -v
```

| Подсистема | Назначение | Разрешённые зависимости |
| --- | --- | --- |
| `core` | Формат пакета и источники | Нет |
| `data` | Датасеты, алиасы и нормализация | `core` |
| `content` | Численные помощники построения рекомендаций | `core` |
| `release` | Подготовка и экспорт текущего выпуска | `core`, `data`, `content` |
| `historical` | Исторические оценки и сравнения MAL 2020 | `core`, `data`, `content`, `release` |
| `research_support` | Исследовательские артефакты, протокол и ресурсы | `core` |
| `research_models` | Модели и предсказания | `core`, `data`, `content`, `research_support` |
| `research_evaluation` | Подготовка исследования, сравнение и оценка | `core`, `data`, `research_support` |
| `research_campaign` | Оркестрация кампании | `core`, `research_support`, `research_models`, `research_evaluation` |
| `entrypoints` | CLI и `__main__` | Остальные девять подсистем |

Импорты внутри одной подсистемы допускаются, но новые циклы не допускаются. Три существующих пересечения границ разрешены только для названных символов: `research_artifacts` берёт `_publish_no_replace` и `_stream_lines` из `dataset`; `research_models` и `research_prepare` берут `release_info` из `release_prepare`. Это переиспользование ограниченного потокового чтения, атомарной публикации и идентичности неизменяемого выпуска. Импорт целого модуля, wildcard или другого символа этими исключениями не разрешается.

Два существующих циклических компонента записаны в политике вместе со **всеми** текущими внутренними рёбрами: диспетчер `research_models` с четырьмя backend-модулями и пара `research_evaluate`/`research_finalize`. Новое ребро даже внутри одного из этих компонентов требует отдельного разбора. `research_models` выбирает backend через конечный словарь `BACKENDS`; проверка читает его литералы из AST и сверяет SHA-256 исходного файла. Изменение этого файла требует повторного аудита динамического импорта и обновления pin, а не автоматического разрешения новых целей.

Проверка просматривает также импорты внутри функций, `TYPE_CHECKING` и `try`, распознаёт буквальные вызовы `importlib.import_module` и `__import__`, включая прямые алиасы. Неизвестные вычисляемые вызовы завершаются ошибкой. Она не импортирует и не исполняет `recsys`; это контроль явно поддерживаемых форм импорта, а не изоляция произвольного Python-кода от рефлексии или доступа к файлам.

При добавлении модуля назначьте ему одну подсистему в политике, затем выполните проверку и её тесты. Если нужна новая зависимость или изменение цикла, отдельно объясните её в задаче и обновите политику после ревью. Перенос родительского каталога с сохранением всех 46 байтовых payload-файлов задокументирован в [миграции layout v1](migrations/arb053-python-src-v1.md). При будущем внутреннем перемещении или изменении файлов производителей нужна отдельная версионированная миграция и новая проверка происхождения; прежние хеши не переписывают. [Архитектурная карта](architecture.md) показывает также границы Rust, PostgreSQL и пакета для бота.
