## Verification contract

The migration audit compares the baseline and task commit using exact Git objects: one unchanged package subtree, 46 file names/modes/objects/bytes, exactly eight removals, and no remaining tracked `recsys/src` or old Python-bot tree. It also checks unchanged lockfiles, boundary policy, Rust and SQL trees, DVC metadata, reports, notebooks and historical ARB-018 provenance. Private versioned evidence has kind `arb-python-source-layout-migration`, schema 1, this layout version, baseline/source SHAs and clean state, old/new prefixes and tree OIDs, per-file SHA-256/size/mode/object records, deleted paths, frozen-file comparisons and historical proof results. Evidence stays outside Git.

Routine checks use the relocated AST boundary guard, synthetic Python and contract suites, `uv lock --check`, a pinned noneditable quality install, and the disposable development-environment test. That test checks all installed `.py`, `.json` and `.md` package files in editable and ordinary wheel modes and verifies wheel rebuild and restore after a temporary Python edit. Required CI also builds the Docker builder from `src/recsys/` and runs the small-fixture first-level stand. These checks do not establish full-catalog ML-02 quality, live Telegram dialogue or deployment acceptance.

Package-relative release, ML-01 and ML-02 names and bytes are preserved by this parent-directory move. Any later rename inside `recsys`, changed producer byte or contract change needs a separate versioned migration and provenance review; historical artifacts are never rewritten in place.
