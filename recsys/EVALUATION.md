# ARB-018 comparison protocol

The measured 20-query report and declared LLM cohort assessment are in [reports/arb018-v1/README.md](reports/arb018-v1/README.md).

`recsys quality compare` evaluates the packaged 20-query set against three fixed methods: the selected GloVe cosine ranker, positive genre Jaccard, and a repaired version of the original notebook method. The query set is purposive, with five queries in each of four popularity bands. It is not a random sample of anime or users. The command checks the pinned catalog, published bundle and build report, source CSV bytes, installed package, Python and dependency versions, and original notebook hashes. It confirms all 20 selected-method rankings, including floating-point scores, against the published bundle.

The repaired legacy method follows the notebook's eligibility path: missing metadata fields exclude a row, the English title replaces Name when available, Source falls back to `Unknown`, and the incomplete Score imputation remains ineffective. It then inner joins nonblank synopsis rows, including boilerplate text. This retains 10,882 of 17,562 MAL anime rows. It encodes 41 binary genres in the recovered order and fits 20 KMeans clusters on unscaled float64 data with `random_state=22`, `n_init=10`, and the other explicit settings in `legacy.py`. It serializes the original metadata field sequence as a Python dictionary, includes numeric cluster labels, removes punctuation, sums matching 300-dimensional GloVe occurrences, and L2 normalizes. For each ready query it sorts cosine candidates, takes 99 before filtering to the same cluster, then sorts by Score, year and numeric MAL ID and returns up to five. It never fills the shortlist after cluster filtering.

This is a repaired comparator. The historical fitted clusters, vectors, package versions and exact row ordering were not preserved. The repairs give stable MAL ID alignment, self exclusion, explicit ties, finite cosine checks, fixed cluster settings and explicit nonready-vector behavior. The source CSV and pinned GloVe files are required; generated matrices and full text are not committed.

Each method and repetition runs in a fresh Python process with native thread limits set to one. The worker prepares its universe and ranks the same 20 requests. Method order rotates across three repetitions. Every worker revalidates the bundle, catalog, manifest, build and normalization reports, and both MAL CSV files, including byte hashes, headers, and IDs. These shared checks are included in measured preparation time even for genre Jaccard, which only needs the catalog for ranking. Selected GloVe and repaired legacy workers then stream and hash the complete GloVe file while preparing vectors. Genre Jaccard checks the GloVe file size but does not read its contents. The legacy worker parses both CSVs a second time to construct notebook-eligible rows. This deliberately measured workload should be considered when comparing preparation times.

Wall-clock preparation, 20-query ranking, parent launch-to-success time, and Linux peak RSS are reported individually and by median, minimum and maximum. The report records machine, runtime, native thread environment, and effective thread pools. These are measurements on a shared development machine. The OS page cache, background host activity, and CPU scheduling were uncontrolled. They do not benchmark generation of the full production neighbor file. Timing has no pass threshold.

The comparison produces `comparison.json`, `legacy-diagnostics.json`, `measurements.json`, `assessment-packet.json`, and `assessment-template.json`. The blinded packet contains a unique, numerically ordered union of query–candidate pairs and catalog evidence only. It excludes method, rank, score, MAL rating, popularity, and run frequency. The packaged `assessment_prompt_v1.md` defines a 0–2 relevance rubric. Complete declared assessor files must cover every pair exactly once and cite exact catalog excerpts from both anime for numeric grades. A null grade means genuinely unassessed or insufficient evidence. Human and LLM assessors remain separate; no grade is fabricated or averaged across assessors.

`recsys quality summarize` verifies the comparison, catalog, measurements, prompt hash and each complete assessment. Its fixed denominator is 100 slots: 20 queries times five. A missing slot contributes zero. A returned candidate with unknown relevance blocks a point estimate for its query and the 20-query macro score; lower and upper arithmetic bounds account for the unknown grade. These bounds are not confidence intervals. Precision@5 counts grades of at least one. Same-franchise concentration is an assessor-judged diagnostic with its own coverage and bounds, not authoritative franchise metadata. The summary gives each query, each assessor, and performance samples; it makes no general improvement claim.

Example, with paths replaced by verified local inputs:

```sh
recsys quality compare --bundle-dir BUNDLE --normalization-report NORMALIZATION_REPORT --build-report BUILD_REPORT --anime-csv ANIME_CSV --synopsis-csv SYNOPSIS_CSV --glove GLOVE --lockfile uv.lock --code-revision COMMIT_SHA --output-dir COMPARISON_DIR --repetitions 3
recsys quality summarize --comparison COMPARISON_DIR/comparison.json --catalog BUNDLE/catalog.json --measurements COMPARISON_DIR/measurements.json --assessment ASSESSMENT.json --output-dir SUMMARY_DIR
```
