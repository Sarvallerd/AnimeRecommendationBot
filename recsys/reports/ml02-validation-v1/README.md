# ML-02: сравнение моделей на validation

Офлайн-сравнение восьми моделей рекомендаций по набору любимых тайтлов нового пользователя. Это итог задачи ARB-042. Test-выборка не открывалась; выбор модели и N — следующий этап (ML-03).

## Постановка

- Данные: Neelagiri Anime Dataset 2025, каталог 28 955 тайтлов, 52 329 861 train-взаимодействий. Пользователи разделены на train/validation/test целиком.
- Запрос: пользователь называет N понравившихся тайтлов (N = 1…10), модель ранжирует весь каталог. Основная когорта — 1000 validation-пользователей с не менее чем 15 понравившимися тайтлами; у каждого 5 скрытых целей, одинаковых для всех N.
- Понравилось = завершено с оценкой ≥ 8. Неоценённое считается неизвестным, а не отрицательным.
- Метрика: NDCG@5, среднее по трём случайным порядкам выбора входных тайтлов. Сравнение с популярным — парный bootstrap по пользователям (2000 повторов, 95% доверительный интервал).

## Выводы

- Лучшая модель — ItemKNN: NDCG@5 = 0.158 при N=10 против 0.099 у популярного.
- Значимо лучше популярного (нижняя граница 95% интервала > 0 для этого и всех больших N): ItemKNN — начиная с N=2; PureSVD — начиная с N=6.
- При одном входном тайтле ItemKNN не лучше популярного: Δ = -0.013. Выигрыш появляется с двух тайтлов.
- Контентная модель на GloVe, на которой построен текущий бот, при N=1 даёт 0.008 — примерно в 12 раз хуже популярного.
- Кривая ItemKNN выходит на плато: точечная оценка отстаёт от максимума меньше чем на ε = 0.01 начиная с N=4. Формальный выбор N по правилу протокола (верхняя граница сожаления) — задача ML-03.
- Если, как сейчас в боте, исключать только введённые тайтлы, то при N=5 72% выдачи ItemKNN — тайтлы, которые пользователь уже оценивал. Для внедрения нужен способ исключать уже просмотренное.

## Ограничения

- Офлайн-оценка восстанавливает известные высокие оценки. Она благоприятна для коллаборативных моделей и популярного и не измеряет «похожесть», которую ищут контентные методы.
- Основная когорта — опытные зрители с длинной историей; короткие истории показаны отдельно и с меньшим числом пользователей.
- Временных меток оценок нет, поэтому это не предсказание следующего просмотра.
- BPR — одна заранее объявленная конфигурация без подбора гиперпараметров.
- Задержка ответа и пропускная способность не измерялись.
