# ML-01 offline evaluation protocol (`ml01-v1`)

This protocol evaluates candidate rankers for recommendations from several liked anime. It does not train a model or select a live bot bundle. The packaged [policy](src/recsys/research_protocol_v1.json) fixes all numerical choices before ML-02 results. The named `neelagiri-2025-nafiul-2026-v1` release lock fixes the Neelagiri 2025 base, Nafiul 2026 aliases and catalog. The historical MAL 2020 preparation commands remain available separately.

The full dataset and accepted release must already exist in private storage. `prepare` validates the entire dataset against its identity and checks the release manifest, catalog hash, base and alias links against the immutable lock. It projects `score: null` for *every* entry in `model-catalog.json` to remove the global MAL rating. No catalog item is removed for cold start, OOV tokens or missing metadata. All generated interactions, split records, query IDs and hidden labels are private; do not commit them, put them in a PR, or publish them in Notion.

Run from an installed, locked worktree package:

```sh
uv sync --locked --no-editable --extra quality
uv run --locked --no-editable recsys research prepare --dataset-dir /private/base --release-dir /private/release --protocol ml01-v1 --code-revision COMMIT_SHA --output-dir /private/ml01-prepared
uv run --locked --no-editable recsys research validate /private/ml01-prepared --expected-identity sha256:PREPARE_MANIFEST_SHA256
```

`prepare` validates the upstream dataset, then makes two streaming passes over `interactions.tsv.gz`. The first writes only train users' completed explicit ratings, computes train-only item statistics, and retains bounded heldout sampling heaps. The second reads selected validation and test users for queries and labels. It never loads all interaction rows into Python memory. Publication uses a new private staging directory and atomic no-replace rename. Deterministic files have canonical JSON or sorted TSV and single-member gzip with fixed header. Manifest identity binds protocol, release lock, dataset, catalog, train and query descriptors, code revision, actual module fingerprints and installed Python/package/NumPy versions. Wall time, RSS and machine paths belong in a separate private measurement record.

The SHA-256 user split uses domain `arb-ml-user-split-v1`, NUL separators, seed 36 and the first eight digest bytes modulo 100: 80% train, 10% validation, 10% test. Partitioning happens before cohort or sampling. Dates of rating events are unknown; this is not a chronological split. Positive means `completed` with explicit rating at least 8. Train fit contains all `completed` explicit ratings 1–10 from train users. Any accepted explicit status enters known history; unrated/missing items have unknown relevance. Validation and test users never enter train interactions or item statistics.

Main users have at least 15 positives. Five fixed targets are chosen by seed 360. From the remaining positives, three independent random-liked orders use seeds 361–363, and a top-rated diagnostic order uses rating descending and seed 364 for ties. The first 10 seeds are reserved. Each order yields nested prefixes N=1…10; N=0 is one train-positive-count popularity reference per user. Short users with 2–14 positives use `min(5,max(1,|P|//3))` targets and `Nmax=min(10,|P|-|T|)`. Heldout sampling uses seed 365 and caps each split at 1,000 main and 250 short users. The short cohort and popularity reference cannot decide the main N. Input row order does not change split, target or seed choices.

A prediction package contains `prediction-manifest.json` and `scores.jsonl.gz`. Its manifest must have schema version 1, kind `arb-ml-predictions`, prepared identity, query and model-catalog descriptors, split, model ID, configuration SHA-256, fit manifest identity, train interactions and stats descriptors, code revision, `zero_seed_policy: popularity-train-positive-user-counts`, and the scores descriptor. The score descriptor contains compressed bytes/SHA-256, rows, uncompressed bytes and canonical SHA-256. Each canonical score row is `{"query_id":"q1_...","scores":[[MAL_ID,score_or_null],...]}` with every catalog MAL_ID exactly once in numeric order. Values must be finite JSON numbers or `null`; `null` means abstention. The N=0 scores must equal exact train positive user counts for all items. Rows must match required queries exactly once and in order. Validation uses `development/queries.jsonl.gz`; test queries become available only after selection. No sampled-negative candidate list is accepted. One score vector is ranked under both masks.

Controlled candidates are all catalog IDs minus known history except the fixed targets. Controlled relevance is those five targets (or the short cohort's fixed target count). Product candidates exclude only supplied seeds; product relevance is all completed positives not in those seeds. Product relevance changes with N and its diagnostic does not support a controlled N comparison. For each eligible candidate, rank by decreasing score then numeric MAL_ID. Ties, abstentions and short lists are deterministic. Duplicate, missing, extra, unknown or excluded IDs fail closed.

At cutoff 5 and 10, binary DCG discounts a hit at one-based rank `i` by `1/log2(i+1)`. IDCG uses the first `min(k, |T|)` ranks. NDCG is DCG/IDCG, Recall is hits/|T|, and HitRate is 1 if any target appears. An empty or short list keeps the original target denominator and scores zero for absent recommendations. The primary validation measure averages NDCG@5 across three random-liked orders *within each main user*, then across users, under the controlled mask. Top-rated, product, short and N=0 results are separate diagnostics. Public reports contain only aggregate fields; slices with fewer than 20 users are suppressed. Coverage, empty/short rate, known-history/completed-repeat share, genre 1−Jaccard with valid-pair coverage, history-length and train-head/tail/cold seed bands, and 2024+ aired/airing seed facts are descriptive. There is no trusted franchise relevance label.

`research evaluate` checks a full immutable prediction package and publishes `evaluation-manifest.json`, private `user-metrics.jsonl.gz` and public-safe `report.json`. `research compare` requires paired query/user identities and uses 2,000 NumPy PCG64(366) user resamples, retaining every order and N for each sampled user. Percentile 2.5/97.5 intervals use lower/higher interpolation. For one fixed model, the N rule uses all ordered N pairs: bootstrap maximum centered pairwise error at percentile 95, then an upper regret bound per N. It selects the smallest N whose bound is at most the prespecified absolute NDCG@5 tolerance 0.01, otherwise reports inconclusive. Fewer than two users have no CI or N choice. These intervals quantify sampling uncertainty, not guaranteed power or live product benefit.

A canonical decision file has this shape (all identities and hashes must be copied from the validation artifacts, not invented):

```json
{"schema_version":1,"prepared_identity":"sha256:...","comparison_identity":"sha256:...","evaluation_identity":"sha256:...","model_id":"chosen-model","config_sha256":"...","fit_identity":"sha256:...","code_revision":"...","n":1,"declared_comparison_arms":["random-liked-1","random-liked-2","random-liked-3"]}
```

The chosen `n` must equal the comparison report's prespecified `chosen_n`; if that report is inconclusive, finalization fails. The decision file itself stays private and its placeholders above are illustrative only.

The last boundary is process enforced. `research finalize` reads only validation evaluation/comparison artifacts and a canonical decision file naming prepared identity, comparison/evaluation identities, chosen model/config/fit/code revision, N and the three declared random-liked arms. It verifies that validation's rule selected that N, then publishes immutable `selection.json`. `research test-queries` requires its exact identity and exports only those three arms at the chosen N. Test evaluation requires the same selection and exact model/config/fit/code revision, and checks the prediction query descriptor against the reconstructed selected test queries. Validation evaluation does not open the test label file, even to hash it. This boundary does not cryptographically embargo labels from an operator with filesystem access; keep them access controlled and run final test once after freezing the decision.

```sh
uv run --locked --no-editable recsys research evaluate --prepared-dir /private/ml01-prepared --expected-prepared-identity sha256:PREPARE_MANIFEST_SHA256 --predictions /private/validation-scores --split validation --output-dir /private/validation-evaluation
uv run --locked --no-editable recsys research compare --evaluation /private/validation-evaluation --expected-prepared-identity sha256:PREPARE_MANIFEST_SHA256 --output-dir /private/comparison
uv run --locked --no-editable recsys research finalize --prepared-dir /private/ml01-prepared --decision /private/decision.json --validation-report /private/validation-evaluation --validation-report /private/comparison --output-dir /private/selection
uv run --locked --no-editable recsys research test-queries --prepared-dir /private/ml01-prepared --selection /private/selection/selection.json --expected-selection-identity sha256:SELECTION_SHA256 --output-dir /private/test-queries
uv run --locked --no-editable recsys research evaluate --prepared-dir /private/ml01-prepared --expected-prepared-identity sha256:PREPARE_MANIFEST_SHA256 --predictions /private/test-scores --split test --selection /private/selection/selection.json --expected-selection-identity sha256:SELECTION_SHA256 --output-dir /private/test-evaluation
```

Initial experimental budget: at most 12 model/config variants; up to 2 hours fit and 1 hour evaluation per variant, 48 hours for the campaign, 8 GiB RSS and 64 GiB for a score artifact. These are planning limits, not observed performance. Full 69M interaction preparation and A/B byte comparison require the accepted private snapshot and are separate from the small synthetic test suite. No ML-02 quality claim or optimal N is established by this implementation alone.
